Medical XAI

January 2026Python, scikit-learn, Flask, React

Ranks 16 conditions from free-text symptoms. Each score is split into text similarity (60%) and symptom overlap (40%), so a reader can see why one condition outranks another.

  1. Pick an example or tap symptoms.
  2. Open How this score was built under a result.
  3. Try the vague example to see the low-confidence message.

      How well does it recover the right condition? (simulated cases)

      At a glance

      The problem
      Symptom checkers usually give an answer with no reasons, so neither a user nor a reviewer can judge or challenge it.
      What I built
      An engine that ranks 16 conditions from free-text symptoms and shows how each score was made (60% text similarity, 40% symptom overlap). It comes with a Flask API, a React interface, and clarifying questions when confidence is low.
      Result
      The right condition was in the top 3 for 96 to 100% of 15,360 simulated cases, and ranked first in 75 to 99% depending on how noisy the input was. Each query takes 7 to 26 ms. The cases are simulated from its own knowledge base, so this measures consistency, not clinical accuracy.
      What it shows
      Explainable AI, NLP with TF-IDF, API design, evaluating a model without labelled data, and running the same model in the browser.

        At a glance
        
            
        
              
        The problem
        Restaurants often plan staff and stock by feel, which wastes food on slow days and understaffs busy ones.
        
              
        What I built
        Pipelines that forecast daily revenue with SARIMA and daily footfall with gradient boosting, run from a command line on any CSV with the right columns. The planner above turns a footfall forecast into revenue and servers needed.
        
              
        Result
        Revenue error fell from 17.3% to 11.7% MAPE against simply repeating last week, and footfall error from 14.8% to 9.0%. The original dataset was lost, so these figures come from synthetic data and show the method, not a real restaurant.
        
              
        What it shows
        Time-series forecasting, feature engineering, spotting and removing data leakage (revenue had been used to predict footfall), validating on future days instead of random ones, and packaging a model with tests.

        Autonomous Engineering Harness
        
            
        September 2026Python, OpenRouter, Pydantic, Typer
        
            
        A coding pipeline built to avoid runaway agent loops. Four model roles plan, write, run and review changes. A deterministic validator, not a model, decides whether a diff is valid, and fixed budgets decide when to stop.
        
          
        
          
        1. Pick a scenario.
        2. Press Step and watch which role acts and how the budgets change.
        3. Compare "Clean pass" with "Block, one re-plan, halt".
        
          
        
            
        Replay a run
        
            
        
            
          
            
          Reviewer PATCH sends one task back to the worker (limit 2). BLOCK sends the plan back to the architect (limit 1). Anything beyond a limit halts the run.
          
            
          
            
            
            
            
              
              
              
            
            
            
            
          
            
          
            
            
            At a glance
            
            
            
              
            The problem
            AI coding agents can loop forever, run up costs and apply broken changes.
            
              
            What I built
            A pipeline of five roles (architect, worker, validator, executor, reviewer) with hard limits: 2 patch attempts and 1 re-plan. Whether a change is valid is decided by deterministic checks, not by the model. Every run leaves a saved audit trail.
            
              
            Result
            Ten tests cover a clean pass, a patch, a rejected change, a block and each limit being hit. A run that cannot succeed stops with its evidence saved instead of retrying forever. It has not been run against live models; the replays above use scripted model replies.
            
              
            What it shows
            Agentic AI design, reliability and safety engineering, and how to test a system built on unpredictable components.

            MLOps Agent
            
            
            December 2025TypeScript, Python, Docker, GitHub Actions
            
            
            Takes a Python model file and generates a deployable project around it: a FastAPI service, Dockerfile, CI for GitHub and GitLab, MLflow tracking, tests and docs.
            
          
            
          
            1. Edit the Python below. Try adding import cv2.
            2. Watch the packages and requirements.txt update.
            3. Open any file of the generated project underneath.
            
          
            
            
            Step 1 of the agent: work out what the model needs
            
            
            
              
            
                
                
              
            
              
            
                
            Packages to install
            
                
            Standard library (nothing to install)
            
                
            requirements.txt
            
              
            
            
            
          
            
          
            
            
            The project it generated from sample_model.py
            
            
            
              
              
              
              
                
              
                
              
              
              
            
              
          
              
          
              
            
              At a glance
              
            
              
              
              The problem
              Every trained model needs the same production scaffolding before it can ship: a service, a container, CI and tests.
              
              
              What I built
              A tool that takes a Python model file and generates a deployable project: a FastAPI service, Dockerfile, GitHub and GitLab CI, MLflow hooks, tests and docs (20 files). It works offline, without an LLM key.
              
              
              Result
              The generated project installs in a clean environment and its 7 tests pass. Running it end to end found and fixed a bug that wrote a package name pip refuses to install. It generates projects; it does not retrain or version models by itself.
              
              
              What it shows
              MLOps, Docker and CI, automation, and testing a tool by running what it produces.
